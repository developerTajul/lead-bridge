05 - RICH DOMAIN MODEL AND SERVICES (CQS)
Binding system instructions. Extends 01-universal-philosophy.txt (P1 rules
9-10, P4, P6) and 02-framework-adapter-laravel.txt (sections 2.2, 4, 5).
Example module used throughout: Coupon.
Load when: writing or changing an Entity, a Value Object, a Command Service,
a Query Service, or a ResponseDTO.
================================================================================

SCOPE NOTE: these rules apply to NEW modules and to modules the prompt
explicitly asks to migrate. Older modules (Category, Brand) keep their
current shape until the prompt asks otherwise (AGENTS.md - STRICT SCOPE
ADHERENCE).

--------------------------------------------------------------------------------
R1. THE ENTITY IS THE SINGLE SOURCE OF TRUTH FOR BUSINESS LOGIC
--------------------------------------------------------------------------------

1. Business rules, invariants, state transitions, and derived business values
   are methods on the Entity (or a Value Object). Never in a Service,
   Controller, Repository, or Mapper.
2. Entities are `readonly` and immutable. A behaviour method enforces its rule
   and returns a NEW Entity instance - it never mutates $this.
3. Entities are created through a named constructor (e.g. Coupon::create())
   and are never allowed into an invalid state. The public constructor is used
   by the Infrastructure EntityMapper to rebuild an Entity from storage.
4. The Entity carries the Domain Events it raised in a readonly list and
   exposes releaseEvents(). It NEVER dispatches them. Every behaviour method
   passes the existing events forward, events are released BEFORE persisting,
   and dispatched only after commit. Full rules: 08-events-and-queues.txt.

5. The Entity never asks the outside world for anything. Time, ids, and random
   values are PASSED IN (e.g. DateTimeImmutable $now), so the Entity stays pure
   and testable. No framework import, no facade, no global helper, no I/O.
6. Business rule violations raise a domain exception
   (<Module><Reason>Exception) from the Entity. The Service catches it and
   converts it to Result::failure with a domain error key.
7. An Entity with only a constructor and public fields is anemic and is a
   defect as soon as the module has any rule, state transition, or derived
   value. Do not invent rules the business does not have, but never leave a
   real rule in a Service.

NOTE ON $id: the Entity's primary key is ALWAYS `?int $id` (null until
persisted), from the first scaffold. A named constructor creates the Entity
before it is saved, so it has no id yet. The ResponseDTO keeps `int $id`
because a ResponseDTO is always built from a persisted Entity (the
ResponseMapper casts: (int) $entity->id). An older Entity scaffolded with
`int $id` is widened to `?int` only when a use case needs create-before-
persist (the store skill's one sanctioned edit to an existing property).

R2. ENTITY TEMPLATE
--------------------------------------------------------------------------------

    <?php

    declare(strict_types=1);

    namespace Core\Coupon\Domain\Entities;

    use Core\Coupon\Domain\Events\CouponRedeemedEvent;
    use Core\Coupon\Domain\Exceptions\CouponExpiredException;
    use Core\Coupon\Domain\Exceptions\CouponUsageLimitReachedException;
    use DateTimeImmutable;

    /**
     * Coupon with its own redeem rules.
     */
    readonly class CouponEntity
    {
        /** @param list<object> $domainEvents events raised by this instance */
        public function __construct(
            public ?int $id,
            public string $code,
            public int $usageLimit,
            public int $usedCount,
            public ?DateTimeImmutable $expiresAt,
            private array $domainEvents = [],
        ) {}

        public static function create(string $code, int $usageLimit, ?DateTimeImmutable $expiresAt): self
        {
            // TODO: guard invariants here (blank code, usageLimit < 1 ...)
            return new self(
                id: null,
                code: $code,
                usageLimit: $usageLimit,
                usedCount: 0,
                expiresAt: $expiresAt,
            );
        }

        public function isExpired(DateTimeImmutable $now): bool
        {
            return $this->expiresAt !== null && $this->expiresAt <= $now;
        }

        public function canBeRedeemed(DateTimeImmutable $now): bool
        {
            return ! $this->isExpired($now) && $this->usedCount < $this->usageLimit;
        }

        /**
         * Redeems the coupon once. Returns a new instance.
         *
         * @throws CouponExpiredException
         * @throws CouponUsageLimitReachedException
         */
        public function redeem(DateTimeImmutable $now): self
        {
            if ($this->isExpired($now)) {
                throw new CouponExpiredException($this->code);
            }

            if ($this->usedCount >= $this->usageLimit) {
                throw new CouponUsageLimitReachedException($this->code);
            }

            return new self(
                id: $this->id,
                code: $this->code,
                usageLimit: $this->usageLimit,
                usedCount: $this->usedCount + 1,
                expiresAt: $this->expiresAt,
                domainEvents: [...$this->domainEvents, new CouponRedeemedEvent(code: $this->code)],
            );
        }

        /** @return list<object> */
        public function releaseEvents(): array
        {
            return $this->domainEvents;
        }
    }

Domain Event (plain PHP, no framework base class):

    namespace Core\Coupon\Domain\Events;

    readonly class CouponRedeemedEvent
    {
        public function __construct(public string $code) {}
    }

--------------------------------------------------------------------------------
R3. VALUE OBJECTS
--------------------------------------------------------------------------------

Use a Value Object when a concept has its own rule and no identity (Money,
Email, DateRange, Percentage). It is `readonly`, validates in its constructor
or named constructor, and compares by value. It lives in the module's Domain
(or in Shared/Domain only if it passes the Shared admission rule in P4).

--------------------------------------------------------------------------------
R4. SERVICES ARE ORCHESTRATORS, SPLIT BY INTENT (CQS)
--------------------------------------------------------------------------------

1. A Service class is EITHER a Command Service (writes) OR a Query Service
   (reads). Never both.
2. A Service contains no business rule. If it needs to decide something about
   business state, that decision is a method on the Entity.
3. Every public Service method returns Result carrying a ResponseDTO (or a
   list of ResponseDTOs). Never an Entity, Eloquent model, paginator, or any
   framework type.
4. Domain exceptions are caught in the Service and converted to
   Result::failure with a domain error key. No exception leaks upward.
5. Services depend only on Contracts (ports), DTOs, and Shared building
   blocks. Constructor property promotion only (see AGENTS.md).

--------------------------------------------------------------------------------
R5. COMMAND SERVICE (WRITE-HEAVY)
--------------------------------------------------------------------------------

Flow for every write use case:

  1. beginTransaction()
  2. Load the Entity through the repository port (existing) OR build it
     through the named constructor (new). When modifying an existing Entity
     inside the transaction, load it with findByIdForUpdate() (a locking
     read), never plain findById(). Apply derived fields (slug, uploaded
     file path) via the Request DTO's with*() clones.
  3. Call the Entity's behaviour method. The Entity enforces the rules.
  4. Release the events from that Entity ($events = $entity->releaseEvents()),
     THEN persist the Entity through the repository port (create(entity) /
     update(entity)). The Entity the repository returns has no events.
  5. commit(). On any failure: rollback() plus cleanup (e.g. delete an
     uploaded file), then Result::failure.
  6. AFTER a successful commit: dispatch $events through
     EventDispatcherContract and push queue jobs through QueueContract.
  7. Map Entity -> ResponseDTO and return Result::success.

Events are dispatched only after commit so a listener never sees data that is
later rolled back. If dispatching fails after commit, log it and keep the
success Result - the write already happened. Never roll back for it.

Sketch (named arguments for multi-parameter calls, positional for single):

    final class CouponCommandService
    {
        public function __construct(
            private readonly CouponRepositoryContract $couponRepository,
            private readonly CouponResponseMapper $responseMapper,
            private readonly TransactionManagerContract $transactionManager,
            private readonly EventDispatcherContract $eventDispatcher,
            private readonly ClockContract $clock,
            private readonly LoggerInterface $logger,
        ) {}

        /**
         * Redeems a coupon once.
         */
        public function redeemCoupon(int $couponId): Result
        {
            $this->transactionManager->beginTransaction();

            try {
                $coupon = $this->couponRepository->findByIdForUpdate($couponId);

                if ($coupon === null) {
                    throw new CouponNotFoundException($couponId);
                }

                $redeemedCoupon = $coupon->redeem($this->clock->now());
                $events = $redeemedCoupon->releaseEvents(); // BEFORE persisting
                $savedCoupon = $this->couponRepository->update($redeemedCoupon);

                $this->transactionManager->commit();
            } catch (CouponNotFoundException $exception) {
                $this->transactionManager->rollback();

                return Result::failure($exception->getMessage(), 'COUPON_NOT_FOUND');
            } catch (CouponExpiredException $exception) {
                $this->transactionManager->rollback();

                return Result::failure($exception->getMessage(), 'COUPON_EXPIRED');
            } catch (CouponUsageLimitReachedException $exception) {
                $this->transactionManager->rollback();

                return Result::failure($exception->getMessage(), 'COUPON_USAGE_LIMIT_REACHED');
            }

            $this->dispatchEvents($events);

            return Result::success($this->responseMapper->toResponseDTO($savedCoupon));
        }

        /** @param list<object> $events */
        private function dispatchEvents(array $events): void
        {
            try {
                foreach ($events as $event) {
                    $this->eventDispatcher->dispatch($event);
                }
            } catch (\Throwable $exception) {
                $this->logger->error('Coupon events failed after commit', ['error' => $exception->getMessage()]);
            }
        }
    }

NOTE: the exact Result::success()/failure() signature and the ClockContract
come from the project's Shared kernel - follow the existing signatures. If
ClockContract does not exist yet, it is a generic technical Shared port
(Shared/Domain/Contracts, adapter in Shared/Infrastructure) and is created
with the use case that needs it.

--------------------------------------------------------------------------------
R6. QUERY SERVICE (READ-HEAVY)
--------------------------------------------------------------------------------

1. No transaction, no events, no queue, no write call on any repository.
2. May use read-optimised repository methods (filters, pagination,
   projections). Hydrating a full Entity is not required when a read model is
   enough, but the repository still returns Domain types - never ORM objects.
3. Returns Result carrying a ResponseDTO, a list of ResponseDTOs, or a
   paginated collection of ResponseDTOs.
4. Constructor takes only what reads need (repository contract, response
   mapper, logger). No TransactionManagerContract, EventDispatcherContract,
   QueueContract, SlugGeneratorContract, or FileUploaderContract.

Sketch:

    final class CouponQueryService
    {
        public function __construct(
            private readonly CouponRepositoryContract $couponRepository,
            private readonly CouponResponseMapper $responseMapper,
        ) {}

        /**
         * Finds one coupon for display.
         */
        public function findCoupon(int $couponId): Result
        {
            $coupon = $this->couponRepository->findById($couponId);

            if ($coupon === null) {
                return Result::failure('Coupon not found.', 'COUPON_NOT_FOUND');
            }

            return Result::success($this->responseMapper->toResponseDTO($coupon));
        }
    }

--------------------------------------------------------------------------------
R7. RESPONSE DTO (ONE OUTPUT FOR EVERY DELIVERY CHANNEL)
--------------------------------------------------------------------------------

1. `readonly class <Module>ResponseDTO` with promoted properties of plain PHP
   types only (scalars, arrays, nested ResponseDTOs, DateTimeImmutable).
2. Built only by <Module>ResponseMapper (Entity -> ResponseDTO). Presentation
   concerns (formatted values, resolved URLs) are added there.
3. The SAME ResponseDTO serves API, Web, Console Command, and WordPress
   delivery. The Service never shapes output for one channel.
4. Formatting the ResponseDTO for a channel is the delivery adapter's job:
   JSON resource, Blade view data, CLI table, WordPress admin notice.
5. Delivery adapters stay thin: validate -> Request Mapper builds DTO -> ONE
   Service method -> translate Result. Use a guard clause on isFailure().

--------------------------------------------------------------------------------
R8. REPOSITORY CONTRACT SHAPE (ENTITY-BASED)
--------------------------------------------------------------------------------

    interface CouponRepositoryContract
    {
        public function findById(int $couponId): ?CouponEntity;
        public function findByIdForUpdate(int $couponId): ?CouponEntity; // locking read
        public function create(CouponEntity $coupon): CouponEntity;
        public function update(CouponEntity $coupon): CouponEntity;
        // TODO: only what the use cases require (ISP)
    }

- findByIdForUpdate() is the locking read used by use cases that modify an
  existing Entity inside a transaction; it is implemented through
  BaseRepository::findRecordForUpdate(). findById() stays the plain read.
- Takes and returns ENTITIES. No loose arrays or DataObjects between Service
  and Repository.
- A repository write method that mutates an existing Entity RETURNS the
  persisted Entity (e.g. updateStatus(Entity): Entity), so the Service maps the
  stored values without a second read. A `void` return forces the Service to
  either map stale pre-write data (a wrong timestamp in the response) or issue
  a redundant read to fetch it back. Neither is acceptable. The adapter
  satisfies this without an extra query: it maps the model the write already
  returned.
- The Infrastructure repository converts with <Module>EntityMapper:
  toEntity(array) and toPersistenceArray(Entity).
- Read-only methods for Query Services may be split into a separate read
  contract when the write contract would otherwise grow fat (ISP).

--------------------------------------------------------------------------------
R9. ANTI-PATTERNS (EACH ONE FAILS REVIEW)
--------------------------------------------------------------------------------

[x] Service reads entity fields and decides: if ($coupon->usedCount >= ...).
[x] Entity with only a constructor and public fields, all rules in the Service.
[x] Entity setters or in-place mutation of a readonly Entity.
[x] Entity calling now(), Carbon::now(), a facade, or any framework helper.
[x] One Service class with both createCoupon() and listCoupons().
[x] Query Service opening a transaction, dispatching an event, or saving.
[x] Service returning an Entity, Eloquent model, or paginator.
[x] Dispatching events before commit.
[x] Entity dispatching its own events.
[x] Repository receiving a DTO or raw array from the Service.
[x] Business rule duplicated in a Controller, FormRequest, or Repository.

--------------------------------------------------------------------------------
R11. DEFINITION OF DONE (RICH DOMAIN + SERVICES)
--------------------------------------------------------------------------------

[ ] Every business rule is an Entity/Value Object method.
[ ] Entity is readonly; behaviour returns a new instance; no framework use.
[ ] Events are plain PHP, carried by the Entity, released via releaseEvents().
[ ] Service is Command OR Query; no business rule inside it.
[ ] Command Service dispatches events/jobs only after a successful commit.
[ ] Query Service performs no write, event, queue, or transaction.
[ ] Repository takes and returns Entities.
[ ] Every Service method returns Result carrying a ResponseDTO.
(Unit tests are paused - AGENTS.md - UNIT TESTING POLICY. Do not write or claim them.)
